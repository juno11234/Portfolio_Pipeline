## 2. 고민과 선택 — 최소 1건 (핵심 기능과 **분리된 독립 섹션**. 없으면 빌드가 깨진다)

### 결정 1: 음식 · 장애물 판별 — 태그 vs 인터페이스(`IHungerObj`)  *(양식 ① 부록 "배고픔 = 속도")*

- 선택지:
    - A. **태그 기반** — 충돌한 오브젝트의 태그로 종류를 구분해 분기
    - B. **`IHungerObj` 인터페이스** — 음식 · 장애물이 인터페이스를 구현하고, 변경량은 인자로 넘김 ← **채택**
- 기준별 비교:

  | 기준 | A. 태그 | B. `IHungerObj` 인터페이스 |
      |---|---|---|
  | 새 종류 추가 | 종류마다 태그를 새로 추가해야 함 | 태그 추가 없이 인터페이스 구현 컴포넌트만 부착 |
  | 코드 중복 | 태그별 분기에 비슷한 처리가 반복됨 | 하나의 경로로 통합 — 중복 제거 |
  | 값 전달 | 종류별로 분기해 값을 정함 | 오브젝트가 든 변경량(`Amount`)을 인자로 넘김 |

- **왜 B 를 골랐나**: 태그 방식은 종류가 늘 때마다 태그를 추가해야 했고, 분기마다 비슷한 코드가 반복됐다. ==인터페이스로 바꾸고 값을 인자로 넘기니== 태그를 추가할 필요가 없어졌고 중복 코드도
  사라졌다. 지금은 시간 감소 · 음식 · 쥐덫이 모두 `HungerController.ChangeHunger` 한 경로를 타고, 배고픔이 바뀌면 `OnHungerChanged` 이벤트로 UI · 연출 쪽에
  알린다.

### 결정 2: 임포트 회전 보정 — Bake Space Transform 일괄 OFF vs 단일 모델만 ON  *(양식 ① 범위 밖 — 부록 7번)*

- 배경: 계층 구조(부모-자식)가 있는 모델은 회전값 0 인 빈 루트가 자동으로 생겨 회전을 흡수하는데, 계층이 없는 단일 모델은 오브젝트 자신이 루트가 되어 !!회전 보정이 깨졌다!!.
- 선택지:
    - A. **모든 모델 Bake Space Transform OFF** — 이전에 냉장고에서 켰다가 자식 Transform 이 바뀌는 문제를 겪고 끈 상태 유지
    - B. **계층 없는 단일 모델만 ON** ← **채택**
- 기준별 비교:

  | 기준 | A. 일괄 OFF | B. 단일 모델만 ON |
      |---|---|---|
  | 계층 모델(냉장고) | 빈 루트가 회전을 흡수해 정상 | OFF 유지 → 정상 |
  | 단일 모델 | 자신이 루트라 회전 보정 문제 | 회전을 0 으로 보정 |
  | 자식 Transform 변경 문제 | 없음 | 자식이 없는 모델에만 켜므로 해당 없음 |
  | 설정 관리 | 규칙 하나 | 모델 구조에 따라 설정을 구분해야 함 |

### 결정 3: 렌더링 최적화 대상 — 드로우콜 vs 그림자 캐스터  *(양식 ① 기능 ⑥ · 기능 ②)*

- 선택지:
    - A. **드로우콜(316) 줄이기**
    - B. **그림자 캐스터(142) 줄이기** — 정적 오브젝트 그림자를 굽기 ← **채택**
- 기준별 비교:

  | 기준 | A. 드로우콜 | B. 그림자 캐스터 |
      |---|---|---|
  | 측정값 | Draw Calls 316 · SetPass Calls 39 | Shadow Casters 142 |
  | 성능 영향 판단 | SetPass 가 낮아(SRP Batcher 가 같은 셰이더를 묶음) 지장 없다고 봄 | 움직이지 않는 정적 오브젝트까지 매 프레임 실시간 그림자맵에 그려짐 |
  | 해결 수단 | 메시 · 머티리얼 합치기, 배칭 | Mixed Light · Shadowmask 로 정적 오브젝트 그림자 베이크 |

- **왜 B 를 골랐나**: 드로우콜 숫자는 높아 보였지만 비용이 큰 SetPass Call 이 39 로 낮아 성능에 지장이 없다고 판단했다. 반면 그림자 캐스터 142 개는 대부분 움직이지 않는 주방
  오브젝트였다. ==정적 오브젝트 그림자를 굽기==로 했고, 베이크 후 !!그림자가 전부 사라지는!! 문제를 셰이더 수정으로 풀었다(→ 3. learnings). 결과 Shadow Casters ==142 →
  15==.

> 결정이 여러 개면 위 블록을 반복. 특정 기능 안의 결정이면 그 기능(양식 ①의 features)에 붙는다고 표시.
